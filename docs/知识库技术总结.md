# OpenAkita 知识库功能 — 技术总结

## 一、功能概述

独立知识库模块，与记忆系统（Memories）完全隔离。用户可上传 PDF、Word、Markdown、TXT 文档，系统自动解析、分块、向量化并存储，在对话中自动注入相关知识或通过工具调用检索。

## 三、数据存储隔离

| 维度 | 记忆系统 (Memories) | 知识库 (Knowledge Base) |
|------|---------------------|--------------------------|
| SQLite | `data/memory/openakita.db` | `data/knowledge/knowledge.db` |
| LanceDB | `openakita_memories` 集合 | `knowledge_base` 集合 |
| API 前缀 | `/api/memories/**` | `/api/kb/**` |
| 前端导航 | 记忆视图 | 知识库视图（独立菜单） |
| 提示词注入 | `## 相关记忆` | `## 来自知识库的相关信息` |

## 四、文档从上传到入库的完整流程

```
用户选择文件 (PDF/Word/MD/TXT, ≤20MB)
        │
        ▼
┌──────────────────────────────────────────┐
│  Step 1: 前端上传                        │
│  KnowledgeBaseView 通过 FormData         │
│  POST /api/kb/upload → 保存临时文件       │
│  返回 {"doc_id": "abc123"}               │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  Step 2: 写入文档记录                     │
│  SQLite INSERT INTO knowledge_documents  │
│  status = 'processing'                   │
│  立即返回 doc_id 给用户（异步后台处理）    │
└──────────────────┬───────────────────────┘
                   │ asyncio.create_task()
                   ▼
┌──────────────────────────────────────────┐
│  Step 3: 文本提取 (extractor.py)          │
│  .pdf   → pypdf / pdfplumber             │
│  .docx  → python-docx                    │
│  .md    → 直接读取 UTF-8                  │
│  .txt   → chardet 检测编码 → UTF-8        │
│  输出：纯文本字符串                        │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  Step 4: 文本分块 (chunker.py)            │
│  策略：按段落分块（默认）                  │
│  规则：                                   │
│    - 以空行分隔段落                        │
│    - 单块最大 1000 字符                   │
│    - 超长段落自动在句号/换行处切分         │
│    - 每个块生成唯一 UUID                  │
│  输出：ChunkResult[] (index, content,     │
│        token_estimate)                    │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  Step 5: 向量化 (嵌入模型)                │
│  调用 get_embedding_model().embed(texts)  │
│  - OpenAI: POST /v1/embeddings           │
│  - 本地: SentenceTransformer.encode()    │
│  输出：float32[row_count][dimension]      │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  Step 6: 双写存储                         │
│  ┌─────────────────────────────────────┐ │
│  │ SQLite (knowledge_chunks 表)         │ │
│  │ 写入每个分块的 id/content/token_count│ │
│  │ 关联 document_id (FOREIGN KEY)       │ │
│  └─────────────────────────────────────┘ │
│  ┌─────────────────────────────────────┐ │
│  │ LanceDB (knowledge_base 集合)        │ │
│  │ Schema: id + vector + document_id   │ │
│  │ 每条记录对应一个 chunk               │ │
│  └─────────────────────────────────────┘ │
└──────────────────┬───────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│  Step 7: 更新状态                         │
│  SQLite UPDATE knowledge_documents       │
│  SET status='ready', total_chunks=N      │
│  删除临时文件                             │
└──────────────────────────────────────────┘
```

**错误处理**：任何步骤失败 → `status='failed'` + 记录 `error_msg`

## 五、对话中知识召回的详细过程

### 方式一：自动注入（每轮对话自动触发）

```
用户发送消息
        │
        ▼
build_system_prompt() 被调用
        │
        ▼
_build_knowledge_section(kb_manager, task_description)
        │
        ├── is_ready()? ──→ false ──→ 跳过（嵌入模型未配置）
        │
        ├── true
        │     │
        │     ▼
        │   kb_manager.search(用户消息前500字符, top_k=3)
        │     │
        │     ├── get_embedding_model()
        │     ├── embed_query(用户消息) → 查询向量
        │     ├── LanceDB.search(向量).metric("cosine").limit(3)
        │     │     │
        │     │     ▼ 返回 [{id, _distance}, ...]
        │     │
        │     ├── 计算 cosine_score = 1.0 - distance/2.0
        │     ├── SQLite 回查: JOIN knowledge_chunks + knowledge_documents
        │     │     获取 content + document_name
        │     │
        │     ▼ 返回 [{chunk_id, document_id, document_name, content, score}]
        │
        ▼
格式化为提示词片段：
  ## 来自知识库的相关信息
  - [《文档A.pdf》]：相关片段内容摘要...
  - [《文档B.md》]：另一段相关内容...
        │
        ▼
注入到系统提示词的 developer section
（与其他部分如记忆、规则、AGENTS.md 并列）
        │
        ▼
LLM 收到完整系统提示词（包含知识库片段）
        │
        ▼
LLM 可选择引用知识库内容来回答用户问题
```

### 方式二：工具调用（LLM 主动检索）

```
对话过程中 LLM 需要更深入的文档信息
        │
        ▼
LLM 调用 search_knowledge_base({query: "...", top_k: 5})
        │
        ▼
KnowledgeBaseHandler.handle() 被执行
        │
        ├── 获取 agent.kb_manager
        ├── kb_manager.search(query, top_k)
        │     （流程同上：向量检索 → SQLite回查）
        │
        ▼
返回 Markdown 格式结果：
  ### 结果 1 — 《文档A》（相关度: 85%）
  片段内容...
  ---
  ### 结果 2 — 《文档B》（相关度: 72%）
  片段内容...
        │
        ▼
LLM 在下一轮推理中引用这些结果
```

## 七、API 端点一览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/kb/upload` | 上传文档（multipart/form-data），返回 doc_id |
| GET | `/api/kb/documents?limit=&offset=` | 分页文档列表 |
| DELETE | `/api/kb/documents/{doc_id}` | 删除文档及所有分块 |
| POST | `/api/kb/search` | 搜索知识库 `{"query":"...","top_k":5}` |
| GET | `/api/kb/status/{doc_id}` | 文档状态（含分块详情） |
| GET | `/api/kb/ready` | 就绪检查（嵌入模型+向量表） |

## 八、安全与限制

| 项目 | 限制 |
|------|------|
| 文件大小 | 上限 20 MB |
| 文件类型 | 白名单：`.pdf` `.docx` `.md` `.txt` `.markdown` |
| 路径遍历 | 已防护（临时文件隔离存储） |
| 嵌入模型未配置 | 知识库功能不可用，其他功能不受影响 |
| 后台任务失败 | 自动标记 `status=failed`，显示错误原因 |
